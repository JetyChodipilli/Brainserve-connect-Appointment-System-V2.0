# Sprint 14 — group visits, visitor kiosk and badges

Scope: V2 requirement P1-10. Group preregistration, signed QR arrival requests, dedicated visitor devices and a browser-print badge template extend the current appointments and access workflow. Kiosk intake is disabled by default. Selected scanner, tablet and printer UAT is pending; automated checks do not certify hardware.

## Behavior and authority

Reception preregisters 2–50 visitors for one host, visit type and available slot. The screen supports HR visits, interviews and client meetings. Every member receives an independent reference and starts at Security intake. Existing Security, Reception, HR/leadership approval and check-in rules remain applicable. No group-wide approval or automatic check-in is introduced. Group registration is atomic: a failed member rolls back the whole group, audit and integration events. An account-scoped request UUID and exact payload fingerprint make an uncertain request safely retryable. The screen locks that payload until its exact retry succeeds; it never automatically resubmits a mutation.

Flyway V70 allows overlapping appointments only when they share an immutable group reservation and exact host, type and slot. Independent visits and other groups still conflict. Individual cancellation retains normal workflow; all reserving members must finish or cancel to free the slot. Changing a group reservation requires canceling and preregistering it. Existing migrations and checksums are unchanged.

System Admin with current SYSTEM_CONFIGURE permission provisions at most 20 active devices per account. A fresh MFA proof is required for provision/revoke. Codes contain 256 random bits, are shown once and expire after eight hours. Only a SHA-256 fingerprint is stored. The owner can list their latest 50 devices and revoke an observed version. Inactive owners or lost role/permission invalidate their devices. Device codes grant no staff API authority.

`/kiosk` is a standalone visitor screen. Its POST-only session/intake transport uses X-Kiosk-Token, omits cookies and Authorization, and never refreshes a staff session. The code stays in memory; reload, navigation or disconnect requires reconnection. Scanner/pasted QR content clears before submission, after a reset, on page hiding and after 60 seconds of inactivity. Pending requests are canceled and stale responses fenced. URL query/hash are removed; tokens are not placed in WebStorage, URLs, audit or diagnostics. Intake replies contain only generic acceptance, with no visitor identity. Configure a dedicated OS/browser kiosk profile with no staff login; this web screen cannot enforce OS restrictions or prevent physical browser escape.

The signed pass is validated against current appointment status and time under a database lock. Only APPROVED visits may request arrival. Tampered, canceled, expired, premature and already checked-in passes reject. Duplicate scans create one request per appointment, including after staff resolution; there is no offline queue or automatic retry. Reception/Security with current QR_PASS_VERIFY sees the oldest 50 pending requests, verifies the visitor using existing controls and marks the observed request reviewed. Resolving a request does not check the visitor in or change occupancy. Redis permits 60 requests/device/minute with an IP fence; unavailable rate state fails closed.

Reception/Security with current QR_PASS_VERIFY and VISITOR_CHECK_IN prepares a badge only for a current unchecked-out access record and CHECKED_IN appointment. Each print re-fetches eligibility. Template 1 shows company name, visitor name, badge/reference, expiry and a signed PNG QR. It is 85.6 × 54 mm; company and visitor names wrap to two lines, with full identity available in the authorized record. Print CSS hides staff controls. Browser Print / Save as PDF is supported; printer SDKs, camera scanning and offline operation are outside this sprint. Printed or saved badges contain personal data and a signed pass; use the organization's handling policy. A printed badge never overrides server expiry, cancellation or checkout checks.

Group labels and request fingerprints are scrubbed after every member passes the existing appointment archive verification and legal-hold anonymization gates. Group/member relationships, device metadata and arrival receipts remain retained operational records without duplicated visitor names in the new tables. Do not include personal data in device labels.

## Deployment and recovery

Apply V70 through Flyway with the existing PostgreSQL btree_gist extension. Deploy matching backend/frontend images. Keep `KIOSK_ENABLED=false` until acceptance. Provision/revoke administration remains available while intake is disabled. For an immediate kiosk stop, disable intake and revoke affected devices. Preserve V70 schema and use a pinned V70-compatible release for application recovery; do not reverse migrations or remove populated group columns/constraints. Restore the complete database rather than individual tables: group links and arrival deduplication depend on their foreign keys.

CI explicitly requires real PostgreSQL/Redis Sprint 14 tests with zero skips. Browser checks cover memory-only credentials, staff-authority separation, duplicate submission, reset/late responses, expiry, generic failures, exact group retries and print checks at mobile/tablet/desktop sizes. Staging runs with kiosk disabled, tests authorization/provision/revoke and retains a canceled two-member group, revoked device and resolved arrival receipt. The restore drill compares all V70 row fingerprints, requires nonempty fixtures, verifies migration 70, starts the app and reapplies pinned images.

## Pending supervised hardware acceptance

1. Reception/Security owner records the selected tablet/browser, USB or keyboard QR scanner, printer, driver and badge stock.
2. In a dedicated OS/browser profile, verify no staff session is available; test reload, 60-second idle reset, page hiding, eight-hour expiry and immediate device revocation.
3. Enable intake in a disposable or supervised pilot environment. Scan a genuine approved pass, duplicate it, then test tampering, early arrival, expiry, cancellation and network loss. Verify no automatic approval/check-in or occupant count change.
4. Complete the normal staff check-in; print and Save as PDF at 100% scale. Confirm 85.6 × 54 mm stock alignment, long names/company branding, QR readability, expiry readability and absent staff controls. Test checkout before print and server rejection after checkout.
5. Record operator, device versions, observed results, limitations and signoff before production enablement. Live Google Calendar and Slack acceptance remain separately pending as documented in Sprints 12–13.
