# BrainServe correction and verification — 15 September 2026

Base: `JetyChodipilli/Brainserve-connect-Appointment-System`, main commit
`f4fe2f7643436f753157e3881b8db921638a73f1`.
This revision supersedes the earlier correction ZIPs. No changes were pushed or deployed.

## Repairs

- The animated Modular Bridge page is included, with both image assets. It appears
  for missing backend configuration, session verification, temporary session/API
  outages, and the short verified-session transition into the authorized workspace.
- Retry stays guarded while pending. Transient session and token-refresh failures
  retain credentials; rejected/revoked credentials still return to login. Controls
  wait for browser hydration, preventing lost early clicks. Pause/resume, connection
  help, responsive layout and reduced-motion support are included.
- An early production return in Reports hid the entire overview. Reports now opens
  an API-backed overview with appointment totals and a dynamically calculated visit
  mix donut. CEO, HR Admin and System Admin paths were exercised in browser tests.
  Existing history filters, cursor pagination, datasets and CSV/XLSX export code remain.
- New authenticated `GET /api/v1/dashboard/visit-types?from=YYYY-MM-DD&to=YYYY-MM-DD`
  groups visits by type within the office date range. CEO/System Admin use company
  scope; HR/Manager/Team Lead use department scope; Employee uses personal scope.
  The endpoint validates a maximum 366-day inclusive range and uses existing tables.
- Missing department assignments cannot fall back to company-wide summary/chart
  data. Dashboard cache keys now include role, employee and department to avoid
  serving values cached under a previous assignment.
- Report refresh failures retain last-good values for the SAME applied range.
  Applying a different range clears the previous values before fetching.
- CEO can read live occupancy through `VISITOR_OCCUPANCY_READ`; check-in/check-out
  powers remain operational-role actions. The Arrived today dashboard card is restored.
- The npm lockfile was regenerated by npm against the registry, including integrity
  hashes, then installed successfully with a real clean `npm ci`. The earlier
  manually reconciled lockfile and dry-run-only verification are superseded.
- Existing shell entry points invoke non-executable helper scripts through bash.

The missing visual identified in the source was the Reports overview/visit chart.
A separate API-request usage meter was not found in the inspected code/history;
this revision does not invent API traffic telemetry or claim to restore that feature.
